# Система учёта оборудования кафедры

Учебный проект по курсу «Управление проектами создания информационных систем».  
**Группа:** ИСТбд-41  
**Ульяновск, 2026**

---

## Карточка проекта

*   **Проблема:** Разрозненные записи на кафедре затрудняют оперативный поиск оборудования, определение текущего материально ответственного лица и быстрое восстановление документов о передаче техники.
*   **Основной пользователь:** Лаборант кафедры.
*   **Получатели:** Сотрудники и преподаватели кафедры.
*   **Предполагаемый заказчик:** Заведующий кафедрой.
*   **Ожидаемый результат:** Локальное веб-приложение, автоматизирующее учет приборов, ведение истории перемещений и генерацию печатных актов.

---

## Границы проекта

Проект жестко локализован рамками одной конкретной кафедры и автоматизацией ее внутренних процессов перемещения материальных ценностей.

| Направление | Входит в первую версию | Сознательно не входит в проект|
| :--- | :--- | :--- |
| **Масштаб и учет** | Одна кафедра; учет отдельных единиц оборудования. | Учет в масштабах всего университета; учет расходных материалов и складских партий. |
| **Операции** | Прием на учет, выдача сотруднику, прием возврата, история операций. | Согласование закупок, расчеты с поставщиками, управление счетами и процедура списания. |
| **Документооборот** | Генерация печатных актов приемки, передачи и возврата в формате PDF с реквизитами операции. | Электронная цифровая подпись; произвольный конструктор отчетов. |
| **Интеграция** | Локальный запуск через Docker Compose; ввод инвентарных номеров вручную. | Интеграция с 1С / бухгалтерией; мобильное приложение; сканирование QR и RFID меток. |
| **Смежные процессы**| Ведение лога состояния. | Бронирование аудиторий; учет ремонтов у подрядчиков; склад запчастей; уведомления студентам. |

## Ключевые пользовательские сценарии

1.  **Приём на учёт:** Регистрация фактически поступившего прибора. Лаборант заполняет карточку (название, номер, кабинет), указывает передающую сторону, сохраняет данные и генерирует первичный акт приемки.
2.  **Поиск и аудит:** Поиск прибора по названию или уникальному номеру. Система отображает его текущее техническое состояние, номер кабинета и ФИО сотрудника, у которого вещь находится на руках.
3.  **Выдача оборудования:** Лаборант выбирает сотрудника кафедры, система автоматически проверяет доступность прибора (он должен быть свободен и исправен). Регистрируется выдача и формируется акт передачи.
4.  **Возврат оборудования:** Лаборант находит активную выдачу, фиксирует фактическое состояние прибора и замечания при наличии. Выдача закрывается, формируется акт возврата, а вещь возвращается в статус «свободна».

## Направления разработки

Вся деятельность команды и бэклог задач структурированы по 4 сквозным эпикам:
1. **1. Организация и требования** — управленческие задачи, фиксация концепции, сбор требований, описание бизнес-правил и логики актов.
2. **2. Серверная разработка** — проектирование реляционной схемы БД, разработка REST API-методов, реализация бизнес-логики и автоматическая генерация структуры документов.
3. **3. Клиентская разработка** — прототипирование интерфейсов, верстка страниц каталога, форм ввода, карточек оборудования и модальных окон, интеграция с API.
4. **4. Интеграция и Тестирование** — составление тест-кейсов, функциональное тестирование сквозных сценариев, исправление дефектов и подготовка демонстрационных данных.
